Next Up Hoops

A real website and system built for a local basketball organization

Links Live website | Video walkthrough | Backend code

Overview

Before this project, the organization shared most of its information through Instagram and word of mouth. Tryout details, schedules, and updates were spread across posts, messages, and screenshots, which made things confusing for players and parents.

I stepped in and built a proper website to bring everything into one place. The goal was to make information easy to find and give the organization a clean and reliable online presence.

This was a real project for a real organization. I worked directly with the owner, attended tryouts, and talked with players and parents to understand what they actually needed instead of guessing.

What I built

  • A public website with clear program and tryout information
  • Online tryout registration with Stripe payments
  • A player dashboard to view registration and status
  • An internal admin dashboard for managing tryouts and decisions
  • Automatic emails for confirmations and results

How players use it

Players can create an account, sign up for tryouts, pay online, and see their current status in one place. This removed the need for constant messaging and follow ups.

How admins use it

The admin side allows the organization to manage seasons, open and close registration, review players, and send result emails. Any changes made by admins show up immediately for players.

Tech used

Frontend

  • React
  • Client side form validation
  • Responsive layout

Backend

  • Node and Express
  • Authentication with JWT
  • Role based access for admins

Database and services

  • PostgreSQL
  • Stripe payments
  • Email notifications

Deployment

  • Vercel for the frontend
  • Render for the backend
  • Custom domain and environment setup

Important context

The organization currently uses the website mainly for sharing information and updates. The backend systems such as accounts, registration, payments, and admin tools were built as part of my own learning.

Those systems were still built and tested end to end with real users and can be used if the organization decides to expand in the future. I included them because I wanted to understand how a full system works in real conditions, not just in small demos.

This project taught me how to build something for real peopl and deal with real-world constraints and it made me a stronger and more well-rounded engineer.
